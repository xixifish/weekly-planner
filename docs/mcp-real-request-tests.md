# Weekly Planner MCP server: real-request tests

Requests typed the way a person would ask them, run through Claude with the MCP server
connected. They check the whole chain: whether the AI picks the right tool, sends the right
input, and explains the result correctly. The code tests (Vitest) can't check any of that.

## How to run

1. **Fill in Expected before running anything.** Look at the app (`localhost:3000`, the same
   dev database the server reads) and write what a correct answer must contain.
2. Run each request in a fresh Claude Code session (`/clear` first), so an earlier answer
   can't help a later one.
3. Note whether Claude called `get_week`, and with what input (expand the tool call to see it).
4. Mark **Pass** only if the answer matches Expected and adds nothing made up. Otherwise
   mark **Fail** and write what went wrong.
5. After changing a tool description, run every request again and add a new results column.
